# UI 목업

`mockup/mdsm_nsm_mockup.html`은 MDS Manager에 NSM 기능을 넣은 웹 화면 목업입니다. HTML 파일 하나이고 외부 라이브러리가 없어 브라우저로 바로 엽니다. 화면에 보이는 값은 모두 예시 데이터(문서용 주소 `10.10.x.x`, `203.0.113.x` 등)입니다.

| 메뉴 | 화면 |
| --- | --- |
| 대시보드 | 네트워크 탐지 수, 진행 중인 공격 스토리, 자산 현황, 시간대·위험도·종류·단계별 탐지, 센서 상태 |
| 탐지 현황 | MDS·MTA·NSM 통합 이벤트 |
| 장비 현황 | NSM 센서 상태(자원, 패킷 누락, 전송) |
| NSM 분석 | 공격 스토리(진행 단계·확산 경로·내러티브·대응), NSM 탐지(목록·상세), 자산 현황(장비 유형·제조사·지문·에이전트), 과거 기록 검색 |
| 대응 현황 | 공격 스토리별 조치 현황 |
| 관리 | 장비 목록·그룹, NSM 룰 정책(사용·위험도·기준·배포), NSM 예외(프록시 경유 기본 예외 목록 포함), 에이전트 정책, NSM 탐지 엔진 업데이트 |

## PoC 리포트로 쓰기 (목업형 리포트)

`tests/run_pcap.sh`(또는 `tests/report_pcap.py`)는 기존 통합 리포트(`<pcap 이름>_report.html`)와 함께 **같은 데이터를 이 목업 화면으로 그린 리포트**(`<pcap 이름>_report_mockup.html`)를 만듭니다. 목업 파일을 그대로 템플릿으로 쓰므로, 목업 화면을 고치면 다음에 만드는 리포트도 같이 바뀝니다.

- 만드는 방법: `tests/report_mockup.py`가 `report_pcap.collect()` 결과를 목업 예시 데이터와 같은 모양으로 바꿔 `<script type="application/json" id="report-data">`에 넣습니다. 목업의 `applyReport()`가 예시 데이터를 이 값으로 바꾼 뒤 화면을 그립니다. 데이터 블록이 없으면 목업 그대로입니다.
- 등급: 센서 값(`nsm_detection.log`의 `severity`)을 그대로 씁니다. 단독 탐지는 `Information`, 여러 단계가 이어진 상관 탐지는 `Suspicious`입니다. 리포트 모드에서는 등급 체계·필터·대시보드(먼저 확인할 탐지 = Suspicious)가 이 두 단계로 바뀝니다. 공격 스토리는 상관 탐지로 확정된 단계가 있으면 `Suspicious`입니다.
- 탐지명·공격 단계·탐지 기준: 목업의 룰 표(`RULES`, 룰별 기본값)에서 채웁니다. 룰 정책 화면의 위험도 칸(Critical·High 등)은 Manager에서 정할 우선순위 예시이며 리포트 등급에는 쓰지 않습니다.
- 끄기: `report_pcap.py --no-mockup`. 다른 경로: `--mockup-out <파일>`.

| 화면 | 리포트에서 |
| --- | --- |
| 대시보드 | 캡처 구간 기준(탐지 수, 진행 중인 스토리, 시간대·위험도·종류·단계별, 자산 현황) |
| NSM 분석 › NSM 탐지 | 탐지 요약 + 근거. 상관 탐지는 공격자별로 가장 긴 체인 1건. 같은 시간대 통신 기록은 기존 리포트의 추정 근거(선별 전송 로그 조인) |
| NSM 분석 › 공격 스토리 | 기존 리포트의 스토리(확정 체인 + 확산으로 이어진 탐지, 같은 공격 인프라, 확인이 필요한 내부 접속). 제목·문장은 자동 생성 |
| NSM 분석 › 자산 현황 | 자산 신호(리졸버가 있으면 자산 단위), 장비 유형·제조사·지문(OUI·Recog·TCP SYN), 식별 근거는 실제 신호 값, 주로 통신한 상대는 흐름 요약 |
| 장비 현황 | 센서 1개(pcap): 패킷 누락, 경고, Manager로 가는 기록량 |
| 관리 › NSM 예외 | 그 실행에 적재된 예외의 id·처리·적용 탐지·적중 수(조건은 로그에 없어 비어 있음), 기본 예외 목록(`EX-pb-*`) 적용 여부 |
| 관리 › NSM 룰 정책 | 룰 표(기본값). 편집은 화면 안에서만 바뀌고 저장되지 않음 |
| 탐지 현황(MDS·MTA), 대응 현황, 보고서, 로그, 과거 기록 검색, 그 밖의 관리 화면 | 숨김(Manager 기능이거나 pcap 에 없는 데이터) |

리포트에는 주소·호스트명·계정 원문이 들어 있습니다. 로컬에서 보는 용도이며 외부로 보내지 않습니다.

## 목업을 고칠 때

- 예시 데이터(`EV`, `STORIES`, `ASSETS`, `DEVX`, `EXC`, `SENSORS` 등)의 모양을 바꾸면 `tests/report_mockup.py`의 변환도 같이 고칩니다. `tests/btest/rules/report-mockup.zeek`가 데이터 블록의 모양을 검사합니다.
- 화면 코드는 내부 주소 판정에 `isInt(ip)`, 날짜에 `e.d`·`s.d`(없으면 `DAY`)를 씁니다. 예시 데이터에 기대는 고정값(`10.`으로 시작하는 주소, `11-18`)을 새로 넣지 않습니다.
- 리포트 모드에서 숨길 화면은 `applyReport()` 끝에서 정합니다.
- 공개 저장소이므로 실제 고객 주소·이름·파일 이름을 넣지 않습니다.
