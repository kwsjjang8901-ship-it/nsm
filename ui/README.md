# UI 목업

`mockup/mdsm_nsm_mockup.html`은 MDS Manager에 NSM 기능을 넣은 웹 화면 목업입니다. HTML 파일 하나이고 외부 라이브러리가 없어 브라우저로 바로 엽니다. 화면에 보이는 값은 모두 예시 데이터(문서용 주소 `10.10.x.x`, `203.0.113.x` 등)입니다.

| 메뉴 | 화면 |
| --- | --- |
| 대시보드 | 네트워크 탐지 수, 진행 중인 공격 스토리, 자산 현황, 시간대·위험도·종류·단계별 탐지, 센서 상태, 탐지 방식(행위·시그니처)과 많이 나온 시그니처 |
| 탐지 현황 | MDS·MTA·NSM 통합 이벤트 |
| 장비 현황 | NSM 센서 상태(자원, 패킷 누락, 전송, Suricata 버전·경보 수·누락) |
| NSM 분석 | 공격 스토리(진행 단계·ATT&CK 흐름·확산 경로·내러티브·대응), NSM 탐지(목록·상세, 탐지 방식·ATT&CK 전술 필터, ATT&CK 기법, 시그니처 정보와 같은 연결 묶음), 자산 현황(장비 유형·제조사·지문·에이전트), 과거 기록 검색 |
| 대응 현황 | 공격 스토리별 조치 현황 |
| 관리 | 장비 목록·그룹, NSM 룰 정책(행위 탐지 룰: 사용·위험도·기준·배포 / 시그니처 룰: ET 카테고리·SID별 사용과 단계 지정·위험도 변환·배포 / ATT&CK 커버리지: 매트릭스·Navigator 레이어 내보내기), NSM 예외(프록시 경유 기본 예외 목록, 시그니처(SID) 조건 포함), 에이전트 정책, NSM 탐지 엔진 업데이트 |

### Suricata 연동 화면

시그니처(Suricata) 탐지 화면은 [`docs/SURICATA_INTEGRATION_DESIGN.md`](../docs/SURICATA_INTEGRATION_DESIGN.md)의 연동이 끝났을 때를 기준으로 그렸습니다. 경보는 Zeek를 거치지 않고 Manager로 바로 오고, Manager가 단계별 탐지 8개(`Suricata_Recon`…`Suricata_Other`)로 바꿔 행위 탐지와 같은 목록·공격 스토리·예외·반복 묶기에 넣습니다. 센서 킬체인 상관에는 들어가지 않고 통합 상관으로 이어집니다.

- 예시 데이터: `SIGS`(SID별 시그니처), `suri()`로 만든 `EV` 항목(`eng:'Suricata'`, `sid`, `sig`, 목적지 역할로 올린 경우 `roleUp`). 같은 연결의 행위 탐지가 있으면 그 탐지에 `also`로 묶이고 시그니처 쪽은 `mergedInto`가 붙어 목록에서 빠집니다.
- 화면: 탐지 목록의 방식 칸·탐지 방식 필터, 상세의 시그니처 정보, 공격 스토리 단계, 대시보드의 탐지 방식·많이 나온 시그니처, 장비 현황의 Suricata 상태, 관리 › NSM 룰 정책 › 시그니처 룰 탭, NSM 예외의 시그니처(SID) 조건. 시그니처 탐지 예외는 "Manager 적용"으로 표시하고 저장하면 바로 반영됩니다. 센서 예외 파일(TSV, 13칸)에는 들어가지 않고, 가져오기에서 시그니처 탐지 범위는 오류로 알립니다. 한 예외에 시그니처 탐지와 행위 탐지를 섞지 못합니다.
- 상세의 기술 상세: 시그니처 탐지는 Manager 공통 이벤트(`engine`, `sig_*`, `community_id`, `role_up`)를 보여 줍니다.
- 리포트 모드에서는 시그니처 탐지가 없으면 이 화면들을 숨깁니다(지금 리포트는 Suricata 경보를 넣지 않음).

### ATT&CK 표시

**공격 단계**(정찰 → 피해 7단계)는 공격 스토리와 킬체인 상관을 잇기 위한 제품 분류로 그대로 두고, ATT&CK는 두 번째 축으로 붙입니다. 전술은 **기법으로 찾고** 공격 단계에서 끌어오지 않습니다. 둘이 다른 룰이 8개 있습니다. 포트·호스트 스캔과 AD 정보 수집은 단계가 정찰이고 전술은 Discovery이며, 웹쉘(Persistence), 원격 실행 3종(Execution), Zerologon(Lateral Movement)도 단계와 전술이 다릅니다.

- 예시 데이터: `ATT`(기법 → 공식 이름·전술), `TACTICS`(전술 14개), `ATT_VER`. Manager는 MITRE 공식 데이터에서 만들고 버전을 고정해 화면에 표시합니다. 목업은 쓰는 기법만 담습니다.
- 기법 값: 행위 탐지는 룰 기본 매핑(`RULES` 5번째 값, 센서 `attack_map`과 같게 유지), 시그니처는 룰 메타데이터 `mitre_technique_id`, 상관 탐지는 센서 `techniques`(구성 탐지 순서). 여러 개를 받으므로 `techs()`로 읽습니다.
- 화면:
  - 탐지 목록: 탐지명 아래 기법 보조 줄, ATT&CK 전술 필터, 기법 ID·이름 검색
  - 탐지 상세: 기법·이름·전술·출처와 MITRE 링크, 단계와 전술이 다르면 안내
  - 공격 스토리: 요약의 기법 수, "ATT&CK로 보면"(시간 순서 기법 흐름), 단계 줄의 기법
  - 관리 › NSM 룰 정책 › ATT&CK 커버리지: 전술 × 기법 매트릭스(행위·시그니처·둘 다, 오늘 탐지 표시), 칸별 룰·시그니처·탐지, 단계와 전술이 다른 룰 표
- Navigator 레이어(4.5): 커버리지와 공격 스토리를 ATT&CK Navigator 파일로 내보냅니다. 기법·점수·탐지명만 넣고 주소·장비 이름은 넣지 않습니다.
- 리포트 모드에서도 ATT&CK 표시와 커버리지 탭이 보입니다(행위 탐지 룰만).

## 통합 상관 목업

`mockup/integrated_story_mockup.html`은 MDS·MTA·NSM 탐지를 묶는 통합 공격 스토리와 통합 상관 룰(Sigma 상관 룰 형식) 화면 목업입니다. 설계는 [`docs/INTEGRATED_CORRELATION_DESIGN.md`](../docs/INTEGRATED_CORRELATION_DESIGN.md)에 있습니다. 이 목업은 통합 분석(통합 공격 스토리·통합 상관 탐지·엔티티 연결)과 관리 › 통합 상관 룰(사전 검증 포함)만 다루고, 나머지 메뉴는 `mdsm_nsm_mockup.html`과 같다고 봅니다. 리포트 템플릿으로는 쓰지 않습니다.

## PoC 리포트로 쓰기 (목업형 리포트)

`tests/run_pcap.sh`(또는 `tests/report_pcap.py`)는 기존 통합 리포트(`<pcap 이름>_report.html`)와 함께 **같은 데이터를 이 목업 화면으로 그린 리포트**(`<pcap 이름>_report_mockup.html`)를 만듭니다. 목업 파일을 그대로 템플릿으로 쓰므로, 목업 화면을 고치면 다음에 만드는 리포트도 같이 바뀝니다.

- 만드는 방법: `tests/report_mockup.py`가 `report_pcap.collect()` 결과를 목업 예시 데이터와 같은 모양으로 바꿔 `<script type="application/json" id="report-data">`에 넣습니다. 목업의 `applyReport()`가 예시 데이터를 이 값으로 바꾼 뒤 화면을 그립니다. 데이터 블록이 없으면 목업 그대로입니다.
- 등급: 센서 값(`nsm_detection.log`의 `severity`)을 그대로 씁니다. 단독 탐지는 `Information`, 여러 단계가 이어진 상관 탐지는 `Suspicious`입니다. 리포트 모드에서는 등급 체계·필터·대시보드(먼저 확인할 탐지 = Suspicious)가 이 두 단계로 바뀝니다. 공격 스토리는 상관 탐지로 확정된 단계가 있으면 `Suspicious`입니다.
- 탐지명·공격 단계·탐지 기준: 목업의 룰 표(`RULES`, 룰별 기본값)에서 채웁니다. 룰 정책 화면의 위험도 칸(Critical·High 등)은 Manager에서 정할 우선순위 예시이며 리포트 등급에는 쓰지 않습니다.
- 끄기: `report_pcap.py --no-mockup`. 다른 경로: `--mockup-out <파일>`.

| 화면 | 리포트에서 |
| --- | --- |
| 대시보드 | 캡처 구간 기준(탐지 수, 진행 중인 스토리, 시간대·위험도·종류·단계별, 자산 현황) |
| NSM 분석 › NSM 탐지 | 탐지 요약 + 근거. 상관 탐지는 공격자별로 가장 긴 체인 1건. 같은 시간대 통신 기록은 기존 리포트의 추정 근거(선별 전송 로그 조인) |
| NSM 분석 › 공격 스토리 | 기존 리포트의 스토리(확정 체인 + 확산으로 이어진 탐지, 같은 공격 인프라, 확인이 필요한 내부 접속). 제목·문장은 자동 생성 |
| NSM 분석 › 자산 현황 | 자산 신호(리졸버가 있으면 자산 단위), 장비 유형·제조사·지문(OUI·Recog·TCP SYN), 식별 근거는 실제 신호 값, 주로 통신한 상대는 흐름 요약 |
| 장비 현황 | 센서 1개(pcap): 패킷 누락, 경고, Manager로 가는 기록량 |
| 관리 › NSM 예외 | 그 실행에 적재된 예외의 id·처리·적용 탐지·적중 수(조건은 로그에 없어 비어 있음), 기본 예외 목록(`EX-pb-*`) 적용 여부 |
| 관리 › NSM 룰 정책 | 룰 표(기본값)와 ATT&CK 커버리지(탐지된 기법 표시). 편집은 화면 안에서만 바뀌고 저장되지 않음 |
| 탐지 현황(MDS·MTA), 대응 현황, 보고서, 로그, 과거 기록 검색, 그 밖의 관리 화면 | 숨김(Manager 기능이거나 pcap 에 없는 데이터) |

리포트에는 주소·호스트명·계정 원문이 들어 있습니다. 로컬에서 보는 용도이며 외부로 보내지 않습니다.

## 목업을 고칠 때

- 예시 데이터(`EV`, `STORIES`, `ASSETS`, `DEVX`, `EXC`, `SENSORS` 등)의 모양을 바꾸면 `tests/report_mockup.py`의 변환도 같이 고칩니다. `tests/btest/rules/report-mockup.zeek`가 데이터 블록의 모양을 검사합니다.
- 화면 코드는 내부 주소 판정에 `isInt(ip)`, 날짜에 `e.d`·`s.d`(없으면 `DAY`)를 씁니다. 예시 데이터에 기대는 고정값(`10.`으로 시작하는 주소, `11-18`)을 새로 넣지 않습니다.
- 리포트 모드에서 숨길 화면은 `applyReport()` 끝에서 정합니다.
- 공개 저장소이므로 실제 고객 주소·이름·파일 이름을 넣지 않습니다.
