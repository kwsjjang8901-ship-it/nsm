**결론:** 검토에서 나온 결함을 모두 고치고, 비어 있던 공격 단계(AD 인증 공격, 외부향 정책 위반, 영향)를 채워 탐지 룰 세트의 기능 목표는 대부분 달성했다. 남은 기능 공백은 HTTPS로 숨는 주기적 C2(TLS/SNI 비커닝)다. 모든 룰이 합성 트래픽 기준으로 탐지·미탐 조건대로 동작하고, 클러스터에서도 상관이 노드를 넘어 이어진다. 다만 **운영 트래픽으로 오탐률을 확인하지 않아 임계값이 실제 망에 맞는지는 아직 판단할 수 없다.** 운영 pcap 탐지 점검과 시범 운영이 남아 있다.

## 7. 한계

- **운영 트래픽 미검증.** 모든 판정은 합성 pcap 기준이다. 임계값은 검토 기준값과 운영 기본값(`nsm_config_fixed.zeek`)을 썼고, 실제 망의 정상 트래픽에서 오탐이 얼마나 나는지 모른다. 확산 룰처럼 관리 서버 예외 등록이 필수인 룰은 배포 설정에 크게 좌우된다.
- **심각도 미구분.** 단일 탐지의 심각도가 모두 `Information`이라 DCSync·랜섬웨어도 스캔과 같은 등급으로 나간다.
- **암호화 구간.** SMB3 암호화 세션(05·06·21), TLS 1.3 인증서(09 자체서명 신호)는 볼 수 없다.
- **HTTPS 비커닝 미탐.** 07 비커닝은 평문 HTTP만 본다. 요즘 C2 대부분이 쓰는 TLS 주기 콜백은 09(인증서·지문 점수)에 걸리지 않으면 놓친다. 검토에서 C2 커버리지의 가장 큰 공백으로 꼽은 N5가 남아 있다.
- **미탐 유형.** 한 대로의 원격 실행(확산 룰은 여러 대 기준), 덮어쓰기·대량 삭제형 랜섬웨어, HTTP 안의 NTLM(05·19).
- **클러스터 한계.** 22 NBNS는 질의와 응답이 다른 워커로 가면 놓친다. 23의 DC 자동 학습은 워커별이라 DC 목록 설정을 권장한다.
- **연동 미완료.** OCSF 변환기가 신규 탐지 15종과 영향 단계를 모르고, 자산 식별 결과(서버 역할)를 예외에 자동 반영하지 못한다.

전체 목록과 대응 계획은 SRS 10장에 있다.

## 부록 B. 운영 pcap 탐지 점검 방법

선별 전송 측정과 같은 pcap으로, 룰별 탐지 건수와 상위 출발지 수를 본다. 결과에는 주소·도메인 원문이 나오지 않는다.

> 이후 `tests/run_pcap.sh <pcap>`이 추가됐다. 같은 점검(탐지 종류별 건수·출발지 수)을 자산 신호·선별 전송 요약과 함께 한 번에 출력하고, 탐지·근거·킬체인·자산을 묶은 통합 리포트(`report.html`)도 만들므로 그쪽을 권장한다. 아래 명령은 기록으로 남긴다.

```bash
mkdir -p /root/detect_run && cd /root/detect_run
zeek -C -r /tmp/<pcap 파일> /path/to/nsm/nsm_rules \
  -e 'redef NSM::log_paths = {}; redef NSM::create_log_dirs = F; redef NSM::meta_export_enable = F; redef Log::default_rotation_interval = 0secs;'
python3 - <<'EOF'
import json, collections
by, src = collections.Counter(), collections.defaultdict(set)
for l in open("nsm_detection.log"):
    r = json.loads(l)
    by[r.get("diagnosis")] += 1
    src[r.get("diagnosis")].add(r.get("attacker"))
for d, n in by.most_common():
    print(f"{n:6d}건  출발지 {len(src[d]):4d}개  {d}")
EOF
```

CIC-IDS2017 Monday는 정상 트래픽만 있는 날이라, 여기서 나오는 탐지는 대부분 오탐 후보다. 운영 pcap에서는 건수가 많은 룰부터 근거(`evidence.log`)를 보고 예외 설정이나 임계를 조정한다.
