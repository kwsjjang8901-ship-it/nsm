## 2. 목적과 범위

원페이저 목적 중 자산 관련 항목:
- 자산 컨텍스트 기반 판단: IP 대신 호스트·역할·중요도로 탐지를 표시
- 미관리 자산 가시화: MDS Agent 미설치 장비 식별 (→ Agent 목록 대조는 Next로 범위 제외)
- Manager 자산 식별: 판정 키 우선순위 머신 계정 > DHCP client-id > MAC > 호스트명+도메인 > IP+시간 구간

| 구분 | PoC 범위 | 범위 밖 |
|---|---|---|
| 센서 | 자산 신호 수집(`asset_signal.log`), nsm_rules 머지 가능한 Zeek 패키지 | Manager 연동(mTLS, spool), 클러스터 운영 |
| 판정 | 리졸버로 Manager 판정 로직 시제품, 리포트(TXT/HTML/CSV) | DB 저장, 화면, Agent 목록 대조, AD·DHCP 로그 연동 |

운영 데이터가 없는 4종은 모두 단말 L2 구간이나 DC 앞에서만 보이는 신호로, PC 식별의 핵심이다. 측정 구간이 맞지 않았던 것이 원인이며(4.4), PC 식별률 미검증과 같은 과제다.

### 4.4 PC 식별률이 낮은 이유

PC를 식별하는 신호는 관측 위치에 따라 나오는지 여부가 정해진다(스펙 6장).

| 신호 | 보이는 위치 | 구간 B에서 |
|---|---|---|
| ARP, DHCP, NBNS/LLMNR/mDNS | 단말과 같은 L2 구간 | 없음 (라우팅 구간) |
| Kerberos, CLDAP, DNS 동적 업데이트 | DC 앞 | 없음 |
| NTLM, SMB | 인증 서버 앞 | 가끔 |
| 프록시 인증 | 프록시 앞 | 프록시가 인증을 쓰지 않음 |

구간 B의 낮은 식별률은 센서 결함이 아니라 관측 위치의 상한이며, 시간별 식별률 곡선이 평평한 것(5분 12.8% → 3시간 9.3%)으로 확인된다.

## 5. 운영 데이터로 발견해 보완한 사항

| 발견 | 영향 | 조치 |
|---|---|---|
| VM 복제 단말의 mDNS 이름 충돌 프로브 | 단말당 가짜 호스트명 70여 개 | 확정 응답만 사용 |
| 프록시에 외부 사이트 이름 집중 | 서버 이름 신호의 97%가 프록시 2대 | 프록시 요청 제외, IP당 상한 |
| 단방향 미러 | 응답측 신호 전무 | 캡처 품질 진단·경고 |
| 비대칭 경로의 MAC 교대 | 가짜 IP 재사용, 서로 다른 서버 오결합 | 연결 기록 MAC은 분할 근거에서 제외, 공유 MAC 기준 강화 |
| 스캔성 연결 시도 72만 건 | 단방향 미러 오경보 | 데이터 연결 기준 판정, 스캐너 IP 표시 |
| NTLM 릴레이 형태(한 IP의 다중 머신 계정) | 신뢰도 "높음"의 가짜 자산, 피해 PC와 오결합 위험 | 해당 IP의 머신 계정 식별 제외, 이상 징후 표시 |
| SSH 호스트 키를 여러 장비가 공유 | 식별 키로 쓰면 오결합 | 참고 정보로만 사용, 공유 현황 표시 |
| SSH 배너 OS 추정 비결정성 | 실행마다 debian/ubuntu 결과 변동 | 판정 순서 고정 |

"오결합보다 중복" 원칙에 따라, 확신할 수 없는 신호는 식별 키로 쓰지 않고 참고 정보로 남기도록 설계했다.

| Zeek 8.x | 일부 신호 미지원 | DNS 동적 업데이트, LDAP 안 NTLM, TCP syslog, SSH group18 호스트 키는 9.x 필요 |

| 센서 Zeek 버전 | **9.x 필수** (LDAP 안 NTLM 등 9.x 전용 신호가 자산 식별·공격 징후에 필요) |
| 미러 위치 요구사항 | 자산 식별용으로 **DC(서버팜) 앞 구간 미러를 권장 구성에 포함**. 사용자 구간만 미러하면 PC 식별은 IP 기반으로 제한됨을 명시 |
| 선별 전송 | `asset_signal`을 메타데이터 선별 전송 대상에 포함 (원본 대비 0.1~0.3%) |
| Manager 자산 식별 | 리졸버 판정 규칙(키 우선순위, 점유 구간, 공유 MAC, 다중 머신 계정, 후보 키 승격 조건)을 엔티티 리졸루션 요구사항으로 이관 |
| 캡처 품질 | 센서 상태 지표로 "데이터 연결 응답 비율"과 응답 없는 연결 시도 상위 IP 제공 |
| 미관리 자산 가시화 | Agent 목록 대조(Next)와 함께, 트래픽 기반 "AhnLab 제품 통신 여부"를 보조 근거로 활용 |
| 라우팅 구간 PC 식별 | DHCP 서버 로그·AD 연동(Next), MeDCore 단말 ID 활용 가능성 검토 |
| 개인정보 | 사용자 계정 이름의 보관 기간·접근 권한 정의. 인증 응답값·URL 값은 수집하지 않음 |
